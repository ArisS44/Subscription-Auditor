# Task 1.4 - Fix Cross-Currency Top-Expenses Ranking

## Summary
Fixed the `top_expenses` ranking in `build_overview()` so it ranks and caps per currency instead of across all currencies mixed together, bringing it in line with the "currency grouped, never converted" principle the rest of the endpoint already follows. Full suite green at 41 passed.

## Details
- Read the actual `analytics.py`, `models/analytics.py`, and `test_analytics.py` first; current state matched the Task Prompt's quoted snippet.
- Replaced the single global `sorted(...)[:TOP_EXPENSES_LIMIT]` with: bucket candidate items into `candidates_by_currency` (a `defaultdict(list)`), then for each currency (iterated in sorted order) apply the existing sort key `(-monthly_equivalent, name)` and the existing `TOP_EXPENSES_LIMIT` cap, extending a flat `ranked` list. Final output order is `(currency asc, amount desc, name asc)` — deterministic and stable.
- Logic-only change: no schema change. `AnalyticsResponse.top_expenses` remains a flat `list[TopExpense]` (each item already carries `currency`); the frontend's generic pagination is unaffected. A portfolio with N active currencies can now surface up to `TOP_EXPENSES_LIMIT * N` items.
- Extended the ranking-block comment to describe the per-currency bucketing and the N-currency consequence.
- Added two tests: `test_top_expenses_ranked_per_currency_not_across` (a numerically huge JPY item does not evict genuine EUR top items; each currency ranked within itself) and `test_top_expenses_capped_per_currency` (6 EUR + 6 JPY → top 5 in each, 10 total, smallest in each currency drops off).
