# Task 1.1 - Subscriptions Migration + Pydantic Models

## Summary
Created the `subscriptions` table (trimmed schema, three CHECK-enum columns, RLS with four `auth.uid() = user_id` policies, two indexes) and the create/update/response/list-response Pydantic v2 models. Migration was applied to the dev Supabase project (User-confirmed) and the resulting schema was verified by direct DB introspection.

## Details
- Scaffolded the migration with `supabase migration new create_subscriptions_table` and wrote it mirroring the `profiles` migration's RLS/comment structure, adapting the key from `auth.uid() = id` (self-keyed parent) to `auth.uid() = user_id` (child table with a distinct owning column). INSERT policy uses `WITH CHECK`; SELECT/UPDATE/DELETE use `USING`. `user_id` FK is `ON DELETE CASCADE`.
- Deferred columns (`service_key`, `is_trackable_by_extension`, `tracked_domain`, `cost_per_hour_target`) deliberately omitted per the trimmed-scope instruction.
- Wrote `backend/app/models/subscription.py`: shared `Literal` enum aliases kept identical to the DB CHECK sets (defense in depth), plus constraints — `price` as `Decimal(ge=0, max_digits=10, decimal_places=2)` mirroring `NUMERIC(10,2)`, `name`/`notes` length caps, `currency` as an ISO-4217 3-uppercase-letter pattern, and `date`-typed fields. Update model is all-optional for PATCH semantics.
- Explained the two new concepts (child-table RLS generalization; CHECK-vs-`Literal` defense in depth) to the User before building, per the teaching cadence, and logged both in `docs/LEARNING_LOG.md` (new Session 7 section).
- External-platform checkpoint: prepared and had the User run `supabase db push` against the dev-linked project. Hit two environment gaps the User resolved (CLI not logged in → `supabase login`; login token not read back from keychain → `SUPABASE_ACCESS_TOKEN` env var). Push finished cleanly; the Docker-daemon warning was benign (local migration-cache only, not the remote apply).

## Output
- `supabase/migrations/20260707113207_create_subscriptions_table.sql` — table, enums as CHECKs, RLS + 4 policies, 2 indexes.
- `backend/app/models/subscription.py` — `SubscriptionCreate`, `SubscriptionUpdate`, `SubscriptionResponse`, `SubscriptionListResponse` + `Category`/`BillingCycle`/`SubscriptionStatus` `Literal` aliases and `Price`/`Currency` constrained types.
- `docs/LEARNING_LOG.md` — Session 7 entries: child-table RLS, CHECK+`Literal` defense in depth.
- Commit `dd159e2` on branch `feat/subscriptions-api`.

## Validation
- Pydantic: inline script confirmed acceptance of a valid payload (defaults resolve: `status=active`, `currency=USD`) and rejection of every invalid case — bad enum for each of the three enums (incl. `billing_cycle='custom'`), negative price, >2 decimal places, price exceeding `NUMERIC(10,2)`, over-length name/notes, empty name, malformed/impossible date, lowercase/short currency, missing required price, plus `SubscriptionUpdate` empty-patch acceptance and `exclude_unset` behavior.
- `ruff check` and `black --check` clean on the model file; full pre-commit suite passed on commit.
- DB introspection against dev confirmed: 14 columns with correct types/defaults/nullability; `relrowsecurity = true`; 4 policies all `auth.uid() = user_id` (INSERT via `WITH CHECK`); 4 CHECK constraints (3 enums + `price >= 0`); both `(user_id, status)` and `(user_id, next_renewal_date)` indexes present.
- User confirmed `supabase db push` to dev finished successfully.

## Issues
None blocking. Two User-side CLI-auth hiccups during the migration push (login required, then keychain token not read back — resolved via `SUPABASE_ACCESS_TOKEN`). No code impact.
