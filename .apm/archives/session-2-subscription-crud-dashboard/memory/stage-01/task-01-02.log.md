# Task 1.2 - Subscriptions CRUD + Cancel + PATCH /me + Tests

## Summary
Implemented the full subscriptions read/write API over strict router → service → db layering (list/create/get/update/delete/cancel) with the hybrid renewal-date logic, added `PATCH /me`, and covered everything with pytest including a real-DB cross-user RLS-denial test. Full suite green (31 passed) and a live smoke test against the running server confirmed every endpoint interactively.

## Details
- **db layer** (`app/db/subscriptions.py`): parameterized asyncpg only — list (optional status/category filter, allowlisted `ORDER BY`, pagination), count, get-by-id, insert, dynamic partial update (allowlisted SET columns), delete, cancel. `_COLUMNS` constant keeps SELECT/RETURNING in sync. ORDER BY column+direction validated via `_SORT_COLUMNS`/`_SORT_ORDERS` allowlists (the one thing that can't be a bind param).
- **service layer** (`app/services/subscription.py`): pure `compute_next_renewal_date(start, cycle, today)` + anchored `_add_months` (no month-drift, clamps Jan 31 → Feb 28). CRUD orchestration on `rls_connection`. Renewal recomputed on update only when `start_date`/`billing_cycle` change AND the client didn't set a renewal date in that same patch. Added a not-found guard on the update return (also satisfies mypy).
- **router** (`app/routers/subscriptions.py`): six endpoints, `Annotated[dict, Depends(...)]` style (avoids B008), Literal-validated query params, `SubscriptionNotFoundError → 404`. `user_id` taken only from `claims["sub"]`, never the body (SubscriptionCreate has no such field). 404 (not 403) for other users' rows.
- **PATCH /me**: `ProfileUpdate` model, `update_profile` db fn (allowlisted), `update_my_profile` service, route in `me.py`.
- **main.py**: registered the subscriptions router; widened CORS `allow_methods` to include POST/PATCH/DELETE (write endpoints now exist).
- Explained the layering, RLS-transaction boundary, and injection walls to the User before building (teaching cadence); logged all three concepts in `docs/LEARNING_LOG.md`.

## Compatibility Concerns
Widened the CORS `allow_methods` in `app/main.py` from `["GET", "OPTIONS"]` to include `POST`, `PATCH`, `DELETE`. This was necessary — the browser would otherwise block all write calls to the new endpoints — but it is a change to shared app config that the frontend and any other surface depend on. No breaking effect (only widens what's allowed); flagged so the Manager is aware the CORS policy changed this session.
