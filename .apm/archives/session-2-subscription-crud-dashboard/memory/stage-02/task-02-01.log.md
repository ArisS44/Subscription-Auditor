# Task 2.1 - Dashboard Shell, Tabs, shadcn Components & Data Hooks

## Summary
Replaced the flat dashboard with a tabbed, collapsible-sidebar shell (React Router layout route + nested
routes), added the Base UI shadcn primitives the subscription features need, and stood up the TanStack Query
hooks + mutations for the subscriptions and analytics APIs. Data hooks verified end-to-end against the live
backend with a real session token. Build, lint, and tests pass.

## Details
- **Context integration:** Read the backend interfaces (`routers/subscriptions.py`, `routers/analytics.py`,
  `models/subscription.py`, `models/analytics.py`, `routers/me.py`, `main.py`) to build hooks against the real
  endpoint paths, params, status codes, and response shapes.
- **Shell (visual decision made with User):** Presented three nav styles; User chose a left sidebar rail.
  Built `DashboardShell` (renders `<Outlet/>`), `DashboardSidebar` (collapsible), page components, and an

## Issues

## Compatibility Concerns
- **Money fields are JSON strings, not numbers.** FastAPI/Pydantic v2 serializes `Decimal` to a string
  (`"price": "15.99"`, analytics `monthly_equivalent` and the per-currency maps too). The hook types were
  corrected to `string`; any later frontend Task consuming these hooks must `Number(...)` at format time, not
  treat them as numbers. This differs from the Task brief's implicit assumption.
- **No `form` shadcn component in this preset.** The base-nova registry ships Base UI's `field` (+`separator`)
  as the form primitive; the classic Radix `form`/react-hook-form wrapper is absent. react-hook-form is not
  installed. The later add/edit-modal Task should plan around `field` (and decide whether to add
  react-hook-form then).
- **react-router is v7, not v6** as the brief stated; the nested-route API is identical, so no impact.
- Dev-only: `.env.local` was copied into the worktree frontend to boot the app (gitignored, not committed).
