# Task 1.2 - LLM Provider Layer (llm.py)

## Summary
Built the provider-agnostic LLM wrapper (`app/services/llm.py`) with a Groq adapter over httpx, the
canonical bilingual Apollon system prompt plus an onboarding variant, environment-only provider/model/key
config, and stubbed-client unit tests. A real streamed Groq completion verified end-to-end.

## Details
- `app/services/llm.py`: provider-neutral internal types (`ToolDef`, `Message`, and the event stream
  `TextDelta`/`ToolCall`/`StreamDone`/`StreamError`), an abstract `LLMAdapter`, and `GroqAdapter`
  (Groq's OpenAI-compatible Chat Completions API over httpx). The adapter isolates the three
  provider-specific differences: (a) tool-def envelope (`function.parameters`), (b) tool-result
  re-insertion (`role:"tool"` + `tool_call_id`), (c) SSE normalization. Streamed tool-call fragments are
  accumulated by index and emitted as one assembled `ToolCall`; text is yielded live. Exposes
  `stream_chat_turn(...)` and one-shot `generate_title(...)`. A registry (`_ADAPTERS`) + `get_adapter()`
  select the provider from config at call time.
- Chose httpx over the `groq` SDK so the three translations stay explicit/testable and the abstraction
  isn't coupled to an SDK — recorded as ADR 0002. Adding a Claude/Anthropic adapter later is a new
  `LLMAdapter` subclass + config, nothing in callers.
- `app/services/prompts.py`: `APOLLON_SYSTEM_PROMPT` + `APOLLON_ONBOARDING_SYSTEM_PROMPT` sharing one
  identity/tone/rules block (neutral tone, on-topic refusal + AI-advice disclaimer, grounding rule,
  destructive-action confirmation discipline), plus `build_system_prompt(preferred_language, onboarding)`
  that appends the runtime language directive (en/el pin; auto detects).
- `app/config.py`: added `llm_provider` (default `groq`), `llm_model` (default
  `llama-3.3-70b-versatile`), `llm_api_key`, `llm_base_url`, and an `effective_llm_api_key` property that
  falls back to the existing `groq_api_key`.
- Logs per-call token usage (counts, provider, model) only — never message content.

## Validation
- Unit tests (11/11, ~0.02s, no network via `httpx.MockTransport`) prove: the tool-def envelope is
  OpenAI-correct, tool results re-insert in the `role:"tool"`/`tool_call_id` shape, streaming normalizes
  text + assembled tool call + usage, HTTP error → `StreamError`, title one-shot strips quotes, and
  provider/model/key come from env (changing `LLM_MODEL` needs no adapter change; unknown provider and
  missing key raise `LLMConfigError`).
- Live end-to-end (User supplied `GROQ_API_KEY` in dev `.env`): streamed turn returned "streaming works."
  with real usage (input=391/output=5); `generate_title` returned "Monthly Streaming Service Costs".
