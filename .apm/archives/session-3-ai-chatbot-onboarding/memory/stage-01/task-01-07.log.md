# Task 1.7 - Provider Migration to Gemini Flash + Exhaustive Prompt Validation

## Summary
Migrated the chat LLM provider from Groq to Google Gemini via a new `GeminiAdapter`
behind the existing provider-agnostic layer (no caller changes), disclosed Google as
a sub-processor, and ran a live validation pass that surfaced and fixed two real
Gemini-specific history-replay bugs. Landed on `gemini-flash-lite-latest` after the
intended `gemini-2.5/3.5-flash` models proved deprecated-for-new-keys or ~60%
`503`-overloaded. All 10 tools, the three Task-1.6 symptoms, and the destructive-
confirmation / leak / injection / gap-filling behaviours pass in clean live tests.

## Details
**Part A — provider migration**
- Added `GeminiAdapter` (`services/llm.py`) over httpx, translating the three provider
  differences: system prompt → `system_instruction`; assistant → `model` role; tool
  results → `functionResponse` parts keyed by name; single-part `functionCall`
  streaming. Registered as `gemini`; selected purely via env (`LLM_PROVIDER`/`LLM_MODEL`/
  `LLM_API_KEY`).
- Extended tool-schema sanitization with a Gemini-strict rewrite (`tools.py`): inline
  `$ref`/`$defs`, collapse nullable `anyOf:[X,null]` → `nullable:true`, keep only
  Gemini-supported Schema keys. **Live-verified against the real API: all 10 tool
  schemas accepted (no 400).** `dispatch` still re-validates every payload against the
  real Pydantic model, so the sanitizer never weakens execution-time validation.
- **Three real Gemini history-replay bugs found live and fixed (regression tests
  added):**
  1. *thought_signature.* Gemini thinking models attach an opaque `thoughtSignature`
     to each `functionCall` part that must be replayed verbatim, or the follow-up turn
     (carrying the tool result) 400s. Every tool-using conversation broke on round 2.
     Now captured from the stream, persisted on the assistant tool call, replayed in
     `format_messages`, and stripped from the Groq path.
  2. *Orphaned tool result.* A tool result whose call is absent (name unrecoverable)
     was emitted with a bogus name `"tool"` → Gemini 400. Now skipped.
  3. *Leading non-user turn (found while the User live-tested).* The sliding
     20-message window can cut mid tool-exchange, so the replayed history starts on an
     assistant/tool turn; Gemini requires contents to begin at a user turn and a
     functionCall turn to follow a user/functionResponse turn, so this 400s **every**
     subsequent message once a conversation grows past the window (even "hi"). Fixed by
     dropping everything before the first genuine user message in `format_messages`
     (subsumes #2 for real histories). Commit `549cedb`.
- Added a bounded retry on transient `503` overloads (retry only before anything has
  streamed, so output is never replayed).

**Part B — prompt validation** (run via a live end-to-end harness driving the real
`chat_svc.stream_turn` against a seeded throwaway user; see Validation).

**Cost governance / usage counter (user-directed in-session):**
- Wired per-day token accounting into the pre-existing (but unwritten) `llm_usage`
  token columns: `db/usage.py::add_tokens`, `services/usage.py::record_token_usage`,
  accumulated per turn in `chat.py`. Content-free, best-effort.
- Added operator-only `backend/scripts/usage_report.py` (per-day requests/tokens/est
  cost; `--by-user`). No new app/API surface.
- Set `CHAT_GLOBAL_DAILY_CAP=2000` in `.env`/`.env.example` as an abuse tripwire
  (enforced before any LLM call). Measured cost ≈ $0.0015/message on flash-lite.

## Validation
- **Offline:** 74 tests pass (`test_llm`, `test_tools`, `test_prompts`, `test_chat`),
  ruff + black clean.
- **Live schema acceptance:** all 10 Gemini-shaped tool schemas accepted (no 400).
- **Live tools (clean per-conversation tests):** all 10 fire correctly —
  get_analytics, query_subscriptions, get_user_settings, render_chart (grounded via
  get_analytics), render_table, add/update_subscription, update_user_settings,
  mark_subscription_cancelled, delete_subscription.
- **Three Task-1.6 symptoms:** no fabricated write on missing details (asks instead);
  no tool-name leak; graceful degradation under 429/503 (rate_limited + retry).
- **Destructive confirmation:** verified in fresh conversations — "Delete my Netflix…"
  and Greek "Ακύρωσε…" both ask for confirmation and only execute after an explicit
  yes/Ναι.
- **Injection resistance / gap-filling / leak:** model refuses injected overrides
  (en + el), asks for missing details rather than inventing, describes capabilities
  without leaking identifiers.
- Multi-turn under realistic load hits no provider rate wall on paid tier + flash-lite.
- **Live user-testing (2026-07-15), via a REPL driving the real engine.** The User ran
  a ~15+ turn mostly-Greek conversation that exercised the full surface and passed:
  bilingual `auto` mode matching each message's language per-turn (Greek turns → Greek,
  an English turn → English); grounded savings math (annual 515.76 → 395.88, saving
  119.88 EUR after a delete — all exact); destructive-confirmation gate honoured in
  Greek (asked before deleting Spotify, executed only after "ναι"); gap-filling on bare
  "add"/"βαλε το σποτιφαι"; a full add → attach manage_url → student-price update flow;
  tool-name-leak baiting, prompt-injection, off-topic (weather), and "future features"
  all correctly refused/redirected; coreference across turns. **Critically, the 15+
  turn length is exactly where the leading-non-user-turn bug used to 400 every message,
  and it did not recur** — confirming fix #3 live. This surfaced fix #3 (the User hit
  the 400 first, which drove the root-cause and fix).

## Issues
The automated validation harness (scratchpad) used one shared 20+ turn conversation
and crude string heuristics, producing several false failures (an injection *refusal*
flagged because it echoed "system prompt"; the word "function" flagged as a leak;
`llm_error`s from the orphaned-tool-result bug under the polluted history). Re-running
each concern in a clean single conversation resolved all of them. The harness is a
throwaway test artifact, not shipped code.

## Compatibility Concerns
- **Frontend Agent (Task 2.1) coordination:** the SSE `error` event now carries
  `reason` values `rate_limited` (429/503, post-retry) and `llm_error`; the chat UI
  must map these to user copy (already flagged from Task 1.6). Persisted
  `messages.tool_calls` JSON gained an optional `thought_signature` field — additive
  and ignored by the render layer (which reads `content`/`structured_payload`), so no
  breaking change.
- Default provider/model changed (Groq/Llama → Gemini flash-lite). Groq remains a
  selectable fallback adapter; its history shape is now built cleanly (extra keys
  stripped).

## Important Findings
- **Deviation from the named model, for good reason.** `gemini-2.5-flash`/`-lite` are
  "no longer available to new users" (404); `gemini-3.5-flash` and `gemini-flash-latest`
  returned ~60% `503 overloaded` under light load. Gemini's *tool-calling itself is
  reliable* (so the Task's Haiku fallback trigger — "if Gemini tool-calling proves
  unreliable" — did not apply); the issue was model *serving* capacity. Resolved by
  selecting the stable `gemini-flash-lite-latest` (100% success in a 8-call probe),
  which does tool-calling correctly. `gemini-flash-lite-latest` is a moving alias;
  consider pinning to `gemini-3.1-flash-lite` later for reproducibility.
- **Gemini free tier is unusable for this app.** Newest flash models cap at **20
  requests/day** free on a new project (confirmed via the quota error), far below
  Groq's ceiling this migration meant to escape. User moved to paid **Cloud Prepay
  €10** (auto-reload OFF) — a genuine total hard cap that cannot be exceeded. The
  app-level `CHAT_GLOBAL_DAILY_CAP` (set to 2000) is a secondary daily tripwire; its
  exact value is worth Manager/User confirmation (€10 is a *total* prepay, not daily).
- **Residual model-behaviour risk — the `<function/…>` tool-call-as-text glitch (for
  Frontend Agent).** It did **not** reproduce on Gemini: Gemini emits tool calls only
  through the structured `functionCall` channel, and the adapter never renders those as
  text, so the leak-as-literal-text symptom appears **specific to Groq/Llama**. A
  frontend display-layer guard is therefore low priority while on Gemini, but should be
  kept in mind if Groq is ever re-selected as the active provider. Separately, the lite
  model is occasionally *over-eager* (adds an unrequested render_table/get_analytics
  alongside the requested tool) — harmless (grounding holds, payloads are validated),
  but the UI should tolerate multiple tool/structured events per turn.
- Token accounting excludes the one-shot title-generation call (its usage is discarded
  by `generate_title`); cost impact negligible. The orphan-skip fix is unit-verified;
  a live long-conversation (>20 messages) re-confirmation was not run to conserve
  credits.
