# Task 1.3 - Tool Registry, Dispatcher & Payload Validators

## Summary
Built `backend/app/services/tools.py`: a name→ToolSpec registry + dispatcher that validates every
tool-call payload with Pydantic before executing and returns a clean, LLM-consumable error on failure.
The Session-3 tool set are thin adapters over the existing subscription/analytics/profile services,
called with the caller's claims so RLS is the cross-user boundary.

## Details
- Registry: `register()` / `get_tool()` / `registered_tool_names()` / `tool_definitions()` (which renders
  each tool's Pydantic model as JSON Schema wrapped in `llm.ToolDef`, so the later chat loop gets
  provider-neutral tool defs). `dispatch(name, arguments, claims)` looks up the spec, coerces/validates
  arguments (accepts a dict or a raw JSON string from a `ToolCall`), Pydantic-validates against the tool's
  model, then calls the handler — returning `ToolResult.failure(...)` with a field-level message on
  validation error and on domain not-found (which includes the RLS "invisible row" case).
- Tools (all thin adapters, each reusing an existing service under `rls_connection(claims)`):
  `add_subscription` (reuses `SubscriptionCreate`, incl. `manage_url`), `update_subscription`
  (`UpdateSubscriptionArgs` = `SubscriptionUpdate` + `subscription_id`), `mark_subscription_cancelled`,
  `delete_subscription`, `query_subscriptions`, `get_analytics`, `get_user_settings`,
  `update_user_settings` (reuses `ProfileUpdate`), `render_chart`, `render_table`. Handler outputs are
  normalized through the existing response models with `model_dump(mode="json")` so tool output is always
  JSON-safe. Out-of-scope `get_subscription_guide` / `get_recommendation` were deliberately NOT added.
- `render_chart`/`render_table` validators (the security-sensitive pair): `chart_type` fixed Literal enum;
  values via a `FiniteNumber` BeforeValidator that rejects bools/strings/NaN/inf; labels/cells via a
  `SafeLabel`/`Cell` BeforeValidator that trims, length-caps (120), and rejects HTML markup (`<`/`>`) and
  control chars; table rows must match column width (model_validator). Structure-only — grounding
  (numbers must derive from a same-turn `get_analytics`) is left to the chat loop as instructed.
- RLS is enforced purely by routing every handler through the existing services with the caller's claims;
  no redundant manual ownership check was added, per the task.

## Validation

  out-of-scope ones), tool_definitions are JSON-Schema objects, unknown tool + malformed payloads for
  add/update/settings/bad-JSON return clean errors, and the full render_chart/render_table validator
  matrix (bad chart_type, non-numeric/NaN/inf values, HTML/oversized labels, row-width mismatch, HTML
  cells) rejects while valid payloads pass. Registration-is-additive test registers a stub tool, dispatches
  it, and confirms existing tools are untouched. Real-DB: add→query round-trip, analytics empty-portfolio
  shape, and the RLS cross-user boundary (user B cannot delete/update user A's subscription — reads as
  not-found; A's row intact).

  rate-limiting rapid user creation); it and the other DB tests pass on isolated re-run. ruff + black clean;
