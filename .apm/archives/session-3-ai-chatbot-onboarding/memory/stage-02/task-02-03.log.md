# Task 2.3 - Onboarding Flow

## Summary
Built a full-screen, resumable onboarding wizard (welcome → choose-method →
chat/manual/skip → extension stub → notifications stub → done → Overview), reusing the
existing chat UI in onboarding mode and the existing add-subscription dialog. User-verified
live and signed off; 109 frontend tests pass.

## Details
Verified both backend contracts before building: `ChatMessageRequest.onboarding: bool` and
`ProfileResponse/ProfileUpdate.onboarding_completed` (already exposed).

**Flow & state.** `onboarding-state.ts` persists step position + chosen method + an `entered`
flag to localStorage (strictly-necessary UI state); `useOnboarding.ts` drives navigation and
completion. The server's `onboarding_completed` is the single source of truth for "done" — local
state only remembers *where* an unfinished user is. Completing PATCHes `onboarding_completed: true`
and clears local progress.

**Entry model (three ways, per the resumability requirement):**
- First-login auto-redirect in `DashboardShell` — only when profile loaded, `onboarding_completed`
  is false, AND `entered` is false. `entered` flips true on first wizard mount, so a user who
  leaves mid-flow is never force-walked back in.
- Slim dismissible "Continue setup" banner on the Overview (`OnboardingBanner`) — shown while
  `onboarding_completed` is false; dismiss is session-only (returns next session until completed).
- Direct `/onboarding` route (auth-guarded, outside the dashboard shell).

**Reuse (no new chat/form components):** the chat method renders `ChatView` with a new
`onboarding` prop, threaded through `streamMessage` as `onboarding: true` in the POST body (changes
only backend prompt framing). The manual method opens the existing `SubscriptionFormDialog`. The
extension/push steps are honest "coming soon" stubs matching the app's `ComingSoonPage` style.

**Design sign-off (interactive):** User chose a top progress-rail + centred-card wizard shell and a
slim top-of-Overview resume bar.

**Live-testing fix:** an i18n key collision — the footer Skip button used `t('onboarding.skip')`
while `onboarding.skip` was also an object (`.title`/`.body`) for the skip screen, so it rendered
i18next's "returned an object" fallback. Renamed the label to `onboarding.skipStep` and added a
Skip-button test (the earlier walkthrough clicked only Continue). Commit `11a60a0`.

## Important Findings
- **First-login auto-redirect affects existing users too.** Any user with
  `onboarding_completed = false` (the DB default — so every pre-existing account that never
  completed onboarding) is auto-redirected into the wizard once on their next dashboard visit. This
  is intended for new users, but in an already-populated environment it also pulls in existing users
  the first time. It's a one-time redirect (the `entered` flag then hands off to the banner), and
  fully skippable, but the Manager should be aware for any prod rollout — a data migration could set
  `onboarding_completed = true` for established accounts if that's not desired.
- Added an in-memory Web Storage polyfill to the shared `test/setup.ts` (this jsdom build ships
  without `localStorage`/`sessionStorage`). Additive; unblocks any storage-backed test.
