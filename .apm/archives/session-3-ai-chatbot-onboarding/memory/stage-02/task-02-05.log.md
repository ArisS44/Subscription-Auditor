# Task 2.5 - CAPTCHA on Auth Forms

## Summary
Added Cloudflare Turnstile to the login, signup, and password-reset-request forms; each blocks
submission until the widget is solved and passes the token as `captchaToken` on the corresponding
Supabase Auth call. Verified end-to-end on dev with Cloudflare's test key.

## Details
- Built a reusable `Turnstile` wrapper (`frontend/src/features/auth/Turnstile.tsx`) rather than adding
  a dependency, matching the project's lean-deps style. It loads the Cloudflare script once
  (module-cached promise, idempotent across multiple form mounts), renders the widget imperatively,
  and exposes a `reset()` handle via `forwardRef`/`useImperativeHandle`. Distinguishes `onExpire`
  (normal token TTL — silently clear) from `onError` (hard failure — surface a message). Uses
  `theme: 'auto'` so it matches the app's dark-mode-primary UI.
- Site key resolves from `VITE_TURNSTILE_SITE_KEY`, falling back to Cloudflare's public always-pass
  test key (`1x00000000000000000000AA`) so local dev works with zero configuration. Added the var to
  `vite-env.d.ts` (typed optional) and `.env.example`.
- Wired all three forms: `signInWithPassword` and `signUp` receive `options: { captchaToken }`;
  `resetPasswordForEmail` receives `captchaToken` on its options arg. Each form gates its submit
  button on `!captchaToken`, and on a failed submit resets the widget + clears the token (Turnstile
  tokens are single-use). Google OAuth and the post-email `updateUser` step are intentionally left
  untouched — neither is captcha-gated by Supabase.
- Reset flow scope: Turnstile goes on `ForgotPassword.tsx` (the `resetPasswordForEmail` request step),
  not `ResetPassword.tsx` (the session-based `updateUser`), which matches Supabase's project-wide
  captcha coverage.
- Added `auth.captcha.error` copy in `en`/`el`.
