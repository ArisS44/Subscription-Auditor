# Task 2.2 - Inline Visuals in Chat

## Summary
Replaced the "coming soon" structured-payload chip with real typed renderers — a generic
Recharts chart (bar/column/line/pie/donut) and a table — chosen from the payload by shape, and
User-verified rendering correctly against the live Gemini backend in dark mode. Live testing also
surfaced two backend/agent currency issues (out of this Task's scope), flagged to the Manager.

## Details
Confirmed the exact payload shapes by reading `backend/app/services/tools.py`: the SSE `structured`
event is `args.model_dump(mode="json")` of `RenderChartArgs` (`{chart_type, title?, currency?,
points:[{label,value}]}`) or `RenderTableArgs` (`{title?, columns:[str], rows:[[str|number]]}`). No
discriminator field — distinguished by shape (`chart_type` vs `columns`). Consulted the `dataviz`
skill before writing any chart code.

**Renderers (all typed components — never `dangerouslySetInnerHTML`):**
- `structured.ts` — typed union + `classifyStructured` shape guards. Re-validates on the client
  (empty rows = valid empty-state; short/over-wide rows padded/truncated; neither shape → `unknown`).
- `ChatChart.tsx` — mirrors the dashboard `CategorySpendChart` conventions (categorical `--chart-*`
  palette by index, compact-currency axis ticks + full-precision tooltips, recessive grid). Header
  names the chart (assistant title when present + localized chart-type). Pie/donut get a legend
  (label + value) and the donut a centre total; bar/column/line rely on axis labels (no legend).
- `ChatTable.tsx` — shared shadcn table primitive; numeric cells right-aligned + `Intl`-formatted,
  strings as plain text.
- `StructuredPayload.tsx` — dispatches by shape; unknown → safe placeholder (never throws).
- `labels.ts::humanizeLabel` — maps backend category enum keys (`ai_tool` → "AI tool", localized via
  the dashboard's `subscriptions.category.*` namespace); other `underscore_keys` → spaces. Applied to
  chart labels and table string cells so enum keys never reach the screen.

**Design sign-off (interactive):** User chose multi-color bars (dashboard-matching) + 240px height;
then, after live feedback, a title+muted-type header and a below-legend + donut-centre-total layout.

**Follow-up fixes from live testing:** raw category enum keys leaking onto chart axes/table cells
(`bbc4e10`); bare unlabeled donut → header + legend + centre total (`e99893d`).

## Important Findings
Recorded in project memory (`chat-cross-currency-and-fx-gap`). For a multi-currency user (6 currencies):
- **Cross-currency charts are meaningless.** `get_analytics` returns per-currency buckets and never
  converts (`analytics.py:~46`); the model flattens all currencies into ONE chart (labels like
  `ai tool (JPY)`), plotting ¥14,161 next to €55.9 on one 0–18K axis. A chart payload has a single
  `currency` field and cannot represent multiple — the renderer draws faithfully; the model should
  render one chart per currency. Same theme as the resolved Top-expenses cross-currency bug.
- **The chat agent can't convert currencies though the app can.** Full FX layer exists
  (`services/fx.py`, `/fx/convert`, `useFxRates`) but no FX/convert tool is registered for the agent
  and get_analytics has no base-currency mode, so "show everything in EUR" is (correctly) refused.
  Fix = register a convert tool or add a base-currency analytics mode. A real feature decision.
