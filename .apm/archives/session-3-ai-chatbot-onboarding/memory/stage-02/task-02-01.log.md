# Task 2.1 - Chat Module, SSE Streaming & Conversation Sidebar

## Summary
Finished the Chat module against the now-fixed Gemini-backed engine: localized all
turn-failure and tool-progress copy, handled multi-tool/multi-structured turns, fixed a
real duplicate-render bug the User found in live testing, added a comprehensive automated
suite (20 → 51 tests), and obtained User design sign-off through a live conversation run.

## Details
Resumed from the prior committed implementation (cherry-picked onto this branch) rather than
rebuilding. Verified against the real backend contract before coding.

**New backend behaviors handled**
- **Error `reason` values.** The backend can emit six reasons, not the two named in the
  Task Prompt: `rate`, `user_daily`, `global_daily` (usage caps), `rate_limited`, `llm_error`
  (provider), and `not_found` (router). The prior UI displayed the backend's raw `message`
  string verbatim — English-only regardless of locale, and one variant ("LLM provider request
  failed") leaked internal wording. Reworked state to hold the machine-readable `reason` and
  resolve copy at render time via `chat.error.<reason>` keys, so a failed turn follows the
  active language and an unknown tag degrades to generic copy. Transient reasons render calm
  grey with a clock icon; hard faults render destructive.
- **Multiple tool/structured events per turn.** `structured` was already an array (append). The
  tool indicator was a single slot showing the raw registry name ("Looking up get_analytics…");
  replaced with an ordered `toolNames` list rendered as a step trail behind friendly
  `chat.tool.<name>` labels, so internal names never reach the screen and an unmapped tool falls
  back to neutral copy.
- **`thought_signature`.** Confirmed no action needed — `StoredMessage.tool_calls` is typed
  permissively (`Record<string, unknown>[]`), so the additive field can't break deserialization.
- **`<function/render_table>` literal glitch.** Confirmed Groq-specific per the prompt; no
  defensive parser added.

**Design sign-off (interactive, per UX convention).** Presented 2–3 concrete options for each of
three unresolved choices and the User selected: (1) assistant replies unbubbled/full-width, user
turns bubbled — chosen so the Task 2.2 charts/tables get the full column; (2) untitled sidebar
rows fall back to a localized creation timestamp (`Chat · 15 Jul, 14:32`) rather than "Untitled
chat", keeping multiple untitled rows distinct and unconfusable with the "New chat" button;
(3) empty state adds three clickable, localized starter prompts that send on click.

**Duplicate-render bug (found by User in live testing).** On turn completion the view invalidated
the history query, awaited the conversation-list refetch, then cleared the optimistic turn. Query
invalidation writes the refetched history into the cache itself, so the completed turn was on
screen twice — once from history, once from the still-set `pending` — for the entire duration of
the list request. Fixed by fetching history outside the cache (`fetchMessages`) and installing it
+ clearing `pending` in one synchronous block so React batches them into a single render; the
sidebar refresh no longer blocks the transcript. Verified the three regression tests FAIL on the
old ordering and pass on the fix (temporarily reverted to confirm), and gave the mocked list
response realistic latency since the duplicate's visibility equals that request's duration.

**Test-infra fix.** The shared `src/test/setup.ts` was missing `afterEach(cleanup)` — with
`globals: false`, Testing Library never auto-registers it, so component renders accumulated in one
document. Added it plus a `scrollIntoView` stub (absent in jsdom). Additive/corrective, no conflict
with existing tests.

## Important Findings
- **CORS dev fragility.** The backend allowlists a single hardcoded dev origin
  (`config.py::cors_allow_origins` default `http://localhost:5173`, no `.env` override). If Vite
  binds any other port (5173 was already taken during this Task, bumping to 5174), every preflight
  returns 400 and the app looks like a dead backend. Any Worker running the frontend can hit this.
  Worth a widened dev allowlist or a documented "must be 5173" note.
- **Rate-limit copy unverified end-to-end.** The `reason: "rate"` render path is unit-tested but
  was never observed firing from the real backend. If a future Task wants live confidence, lower
  `chat_user_per_minute` temporarily.
- Structured payloads currently render as a placeholder chip only; the typed chart/table renderers
  remain Task 2.2's scope (unchanged assumption, restated for clarity).
