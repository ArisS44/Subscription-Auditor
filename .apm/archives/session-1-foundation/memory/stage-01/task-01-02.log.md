## Compatibility Concerns
1. **eslint/prettier integration approach deviates from a straightforward mirror hook**, as anticipated by the Task Prompt's Instruction Accuracy note. The frontend's flat `eslint.config.js` pulls in `typescript-eslint`, `eslint-plugin-react-hooks`, and `eslint-plugin-react-refresh` — a generic `mirrors-eslint`-style pre-commit hook runs in its own isolated environment and can't see these already-installed plugins. Used `repo: local` + `language: system` hooks that shell into `frontend/node_modules/.bin` instead, wrapped in a small bash loop that strips the `frontend/` path prefix pre-commit passes (since it invokes from the repo root, but eslint/prettier need to run with `frontend/` as their working directory to resolve the flat config and `.prettierrc.json`). This means these two hooks only work on a machine where `npm install` has already been run inside `frontend/` — they will silently skip with a shell error if `frontend/node_modules` is absent. Any Worker touching `.pre-commit-config.yaml` later should preserve this local-hook pattern rather than switching to a mirror, or document the change.
2. **First `pre-commit run --all-files` was not a no-op** — it surfaced real trailing-newline and Prettier-formatting drift in files from Tasks 1.1/1.3 (frontend scaffold) and the spec doc, contrary to the Task Prompt's expectation that "both already pass their own lint/format locally." Fixed and committed separately (`ea0923e`) from the baseline config itself (`aca4b2a`) so the two concerns are reviewable independently.

## Important Findings
- `pre-commit` is not installed globally on this machine and had to be added via `uv tool install pre-commit`; the binary lands in `~/.local/bin`, which is not on the default `PATH`. Any Worker or the User running `pre-commit` commands in a fresh shell will need `export PATH="$HOME/.local/bin:$PATH"` (or `uv tool update-shell`) first, or install it another way (e.g. `pipx install pre-commit`). Not documented as a project-wide setup step beyond the README's `uv tool install pre-commit` line — worth confirming this matches how the User actually wants pre-commit distributed to future contributors/machines.
