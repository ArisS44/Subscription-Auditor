# Task 4.1 - Azure Provisioning & Key Vault

## Summary
Verified all previously-provisioned Azure resources were intact, resolved the Static Web App region
blocker via an in-place Pay-As-You-Go subscription upgrade, created the Static Web App, wired the real
CORS origin through Key Vault into the Container App, and closed the Supabase prod redirect allowlist
step.

## Details
1. Verified live state with the User (README §7 checklist): resource group, ACR, Container App
   (system-assigned identity, both role assignments: `AcrPull` on ACR, `Key Vault Secrets User` on Key
   Vault), Key Vault with all 7 required secrets, and Application Insights all existed and were correct.
   Only the Static Web App was missing, confirming the User's own assessment.
2. Diagnosed the SWA blocker: the subscription (Azure for Students) had a `sys.regionrestriction` policy
   assignment limiting deployments to 5 regions, none of which support Static Web Apps.
3. Guided the User to upgrade the subscription via the Azure Portal (Cost Management → "Upgrade") rather
   than create a new subscription. This converted the *existing* subscription in place (same
   subscription ID `eca9aea6-...`) to Pay-As-You-Go — all existing resources were preserved with no
   move/recreate needed, and the region-restriction policy assignment was removed entirely as a result.
   This deviated from the Task Prompt's assumption that Azure for Students subscriptions can't convert
   in place; verified empirically via `az account list` (same subscription ID before/after) and
   `az rest` against the policy assignment (returned `PolicyAssignmentNotFound` after upgrade).
4. Guided the User to set a subscription-level Azure Budget (Portal → Cost Management → Budgets):
   €10/month, alerts at 50/80/100%, before creating any further resources.
5. Created the Static Web App (Free tier) in `westeurope` — Static Web Apps has its own separate list of
   supported regions independent of the (now-removed) subscription policy, and `germanywestcentral`
   (used for every other resource) isn't on it.
6. Updated the Key Vault `cors-allow-origins` secret to the real SWA URL and forced a new Container App
   revision (`cors-update`) to pick up the change; confirmed `provisioningState: Succeeded` and
   `runningStatus: Running`.
7. Guided the User to add the SWA URL (as a wildcard, `https://<host>/**`, covering both the
   `/dashboard` OAuth-login redirect and `/reset-password` password-reset redirect used in
   `frontend/src/routes/auth/`) to the **prod** Supabase project's Auth → URL Configuration → Redirect
   URLs; confirmed via screenshot.
8. Amended `infra/azure/README.md` (§5) to document the actual SWA region (`westeurope` instead of the
   default `$LOCATION`/`germanywestcentral`) and the in-place subscription-upgrade path taken. Appended
   a Session 6 entry to `docs/LEARNING_LOG.md` covering ACR/Container Apps, managed identity + Key Vault
   references, the SWA region-support distinction, and the subscription upgrade.

## Important Findings
- **Task Prompt assumption was wrong and should inform future guidance:** Azure for Students
  subscriptions *can* be upgraded to Pay-As-You-Go in place via the Portal's Cost Management →
  "Upgrade" flow, preserving the subscription ID and all existing resources with no move/recreate step.
  The Task Prompt assumed this wasn't possible and planned for a resource-move-or-recreate decision that
  ultimately wasn't needed. Confirmed empirically (unchanged subscription ID in `az account list`
  before/after; region-restriction policy assignment removed as a side effect of the upgrade).
- Static Web Apps' region support is a second, independent restriction on top of any subscription
  policy — even subscriptions with no region policy at all still can't create a Static Web App in every
  Azure region (e.g. not in `germanywestcentral`, used for every other resource in this project). Any
  future resource-region planning should check the resource-type-specific supported-region list, not
  just subscription-level policies.
