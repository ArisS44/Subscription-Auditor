# Task 3.1 - Frontend Skeleton

## Summary
Scaffolded the React 19 + Vite + TypeScript frontend in place under `frontend/` with strict TS,
Tailwind CSS v4 + shadcn/ui (dark mode default), React Router v6, react-i18next (en/el, fully keyed),
a TanStack Query provider, Supabase/backend API client stubs, and a Dockerfile satisfying the Compose
`frontend` service contract. All validation criteria pass.

## Details
1. Scaffolded via `create-vite@latest --template react-ts --overwrite --eslint`, preserving the
   existing `.env.example`. Added `strict: true` to `tsconfig.app.json` (not on by default), Prettier
   + `eslint-config-prettier`, and a real README.
2. Installed Tailwind v4 (`@tailwindcss/vite` plugin, CSS-first config via `@import 'tailwindcss'` —
   no `tailwind.config.js`). Ran `npx shadcn@latest init --template vite -b base -p nova`, which
   generated `components.json`, `src/components/ui/button.tsx`, `src/lib/utils.ts`, and the
   light/dark CSS variable sets in `src/index.css`. Set `class="dark"` on `<html>` in `index.html` so
   dark is the default regardless of OS preference. `lucide-react` came in as a shadcn dependency
   automatically.
3. Added React Router v6 (`Landing`, `Dashboard` placeholder routes, no auth), react-i18next scaffold
   (`src/i18n/index.ts` + `locales/en.json` / `locales/el.json`, all UI strings keyed under
   `landing.*` / `dashboard.*` / `nav.*`), and a `QueryClient`/`QueryClientProvider` wrapping the app
   in `src/App.tsx`.
4. Added `src/lib/supabase.ts` (throws if `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` missing) and
   `src/lib/api.ts` exporting `apiFetch(path, options)` where `options.accessToken` becomes the
   `Authorization: Bearer <token>` header — shaped for the next task to attach a Supabase session
   token without changing this file. Added `frontend/Dockerfile` (installs deps, runs
   `npm run dev -- --host 0.0.0.0`, exposes 5173) and `.dockerignore`.
5. Committed in two increments on `feat/frontend-skeleton`: scaffold+Tailwind/shadcn, then
   routing/i18n/query/clients/Dockerfile.

## Important Findings
- **React version deviation:** the Task Prompt specifies React 18, but `create-vite@latest`'s
  `react-ts` template currently scaffolds **React 19**. Per Instruction Accuracy guidance, proceeded
  with React 19 (current ecosystem default; shadcn/ui, react-router-dom, react-i18next, and TanStack
  Query all support it) rather than pinning backward. Flagging in case downstream tasks assumed
  React 18 APIs.
- **shadcn/ui generator uses Base UI, not Radix:** the `nova` preset pulls in `@base-ui/react`
  rather than `@radix-ui/*`. Base UI's polymorphism API is a `render` prop, not Radix's `asChild` —
  relevant if a later task adds more shadcn components expecting Radix's `asChild` pattern from
  older shadcn documentation/examples.
