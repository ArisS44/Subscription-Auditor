# Task 4.1 - Custom SMTP Provider

## Summary
Production Supabase Auth now sends transactional email through Brevo instead of Supabase's shared
sender. Verified by signing up five times in quick succession — all delivered, none rate-limited, and
the message landed in the Gmail inbox rather than spam. The beta blocker is removed.

## Details

**Provider selection was re-verified rather than taken from the prompt, and this changed the answer.**
Resend — the obvious first choice and the one I would have recommended from memory — is unusable here:
without a verified domain it restricts sending to `onboarding@resend.dev` **and only to the address the
account signed up with**. Beta testers would have received nothing, and the failure would have looked
identical to the defect being fixed. The project owns no domain, so this ruled Resend out entirely.

Brevo was selected: **300 emails/day** free, SMTP relay included, and — decisively — it permits **single
sender verification via a 6-digit code** sent to any address, with no domain required. Mailjet
(6,000/month) was presented as an alternative but its no-domain path could not be confirmed from its own
documentation, so it was not recommended.

**Configured on production only.** Sender `arisskyllas2004@gmail.com` verified in Brevo, SMTP relay
wired into Supabase Auth, and Supabase's own hourly email cap raised to 100/hour — it enforces that
independently of the provider, so leaving it low would have substituted one limit for another.

**Deliverability was better than predicted, for a reason worth recording.** Brevo warns that
free-provider sender addresses land in spam. In practice Brevo **rewrites the envelope sender to its own
authenticated subdomain** (`arisskyllas2004@11795371.brevosend.com`, valid SPF/DKIM) while preserving the
display name. The test message reached the inbox. The predicted spam problem did not materialise, and
the user-facing "check your spam" warning is therefore advisable but not essential.

**Verified by doing, not by inspecting configuration:** five consecutive signups all delivered, no
`over_email_send_rate_limit`, sender shown as `Subscription Auditor`, no postal address in the body.

**Dev deliberately left on the shared sender** at the User's direction. Recorded as an accepted
dev/prod difference rather than an oversight.

## Important Findings

**1. Auth emails are English-only, and this is the one user-facing surface that is not bilingual.**
Supabase Auth templates are a single fixed template per project with no per-user language selection, so
a Greek user signs up through an entirely Greek interface and receives an English confirmation email.
Push notifications *are* bilingual off `profiles.preferred_language` and were verified in both languages
in Task 3.2, which makes the inconsistency sharper. Resolving it means either a template carrying both
languages or sending confirmations from the backend. Worth a Manager decision.

**2. The SMTP key expires after 90 days of inactivity, independently of its 2027 expiry date.** A
personal project can easily pass 90 days with no signup or password reset, after which the key dies on
its own and signups fail silently — the same symptom as the original blocker, months later, with no
apparent cause. Documented in `infra/supabase/EMAIL.md` as the first thing to check if signup emails
stop arriving.

**3. Resend's free tier is a trap for exactly this use case.** Recorded so no future Task reaches for
the popular choice: without a verified domain it only delivers to the account holder's own address.

**4. The User approved a spam-folder line for the "Check your email" screen** (`auth.signup.checkEmailBody`
in both locales), and approved the Greek wording. It was **not** implemented here — the User asked that
it ride along with the Greek translation review Task so that one deploy carries both. Wording agreed:
EN "If it's not in your inbox, check your spam folder." / EL "Αν δεν το βρείτε στα εισερχόμενα, ελέγξτε
τον φάκελο ανεπιθύμητων."

**5. The User wants a deploy after the translation Task**, to close the day. Nothing in this Task
required one.
