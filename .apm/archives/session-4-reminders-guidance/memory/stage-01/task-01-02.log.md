# Task 1.2 - Onboarding First-Login Fix

## Summary
Moved the first-login onboarding decision out of a post-fetch effect inside the dashboard into a routing gate that resolves during render, ahead of the dashboard. All three diagnosed failure modes are fixed; verified by the full test suite, a clean production build, and a live new-account signup.

## Details
The diagnosis in the Task Prompt was confirmed accurate against the code (line numbers and mechanics matched), so the fix targeted the verified root cause rather than a cache-only patch.

- **Root cause / core fix:** `DashboardShell.tsx` decided the redirect in a `useEffect` (post-`/me`-fetch) while rendering `<Outlet/>` unconditionally, so the Overview and its queries always mounted first. Introduced `frontend/src/features/onboarding/OnboardingGate.tsx`, which owns `useMe` and decides during render: it shows a loading state while `/me` is in flight, redirects a brand-new user with a declarative `<Navigate to="/onboarding" replace/>` (so the dashboard never mounts for them), and only otherwise renders its children. Wired it in `App.tsx` wrapping `<DashboardShell/>` inside `ProtectedRoute`. Stripped the redirect effect (and now-unused `useMe`/`readProgress`/`useNavigate`) from `DashboardShell`, leaving it presentational.
- **Latent stranding fix:** the old guard required truthy `meQuery.data`, so a failed `/me` never redirected and surfaced nothing. The gate now renders an explicit error state with a retry button on `meQuery.isError`.
- **Double-wizard fix:** `useUpdateProfile` (`hooks/useMe.ts`) only invalidated `['me']`; with the wizard mounted there is no active `['me']` observer, so invalidation marked the entry stale without refetching, and returning to the dashboard read a stale `onboarding_completed: false`. It now writes the profile the PATCH returns into the cache via `setQueryData(['me', accessToken], profile)` before invalidating, so the gate reads the fresh value immediately.
- **Resumability preserved:** the gate redirects only when `!onboarding_completed && !readProgress().entered`. The `entered` flag (set on first wizard mount, persisted) means a user who exits mid-flow is not force-redirected and resumes via the Overview banner.
- Added `onboarding.gate.*` i18n keys (loading / errorTitle / errorBody / retry) in both `en` and `el`.
