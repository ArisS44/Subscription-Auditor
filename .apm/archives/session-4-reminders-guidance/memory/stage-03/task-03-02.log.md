# Task 3.2 - Live End-to-End Verification

GitHub cron trigger → job endpoint → due query → push delivery → real device — ran end to end for the
first time and worked, in both languages. Three defects surfaced that no test could have caught; two

**Signup and CSP (verified first, as the least-tested path).** Production signup completed with the
real Turnstile CAPTCHA and no CSP violations. The CAPTCHA was confirmed real rather than the
always-passing test key by inference from the outcome, not by the badge: prod Supabase enforces

Greek with correct `el` locale formatting (`01/08/2026`, `7,99 EUR` with decimal comma), selected
server-side from `profiles.preferred_language`.

**Idempotency** was proven by dispatching a second time: no new notifications, exactly one ledger row
per subscription, timestamps unchanged.

**Precedence and suppression** were proven in a single round designed as a negative control. Spotify
(renewal 6 days out, per-subscription override of 10) fired, which the profile default of 3 could not
have produced; Disney+ (cancelled) and HBO Max (paused), both dated inside any window, stayed silent.
These three rows were created **through the chatbot** in mixed languages (Greek for two, English for
one) and every field landed exactly as specified — no fabricated values, no wrong-target writes.

**English notification copy** verified by switching `preferred_language` and dispatching again.

**Revocation** initially failed silently (see Important Findings), was fixed, deployed, and re-verified:
`204` and zero rows in `push_subscriptions`.

**Cold start.** After 12 minutes of complete idle the container was still `Running` with 1 replica and
answered in 0.21s — it had not scaled to zero at all, so the scale-down delay is longer than 12
minutes and cold starts are rarer than the Manager's 22.2s measurement implies. The User directed that
a formal cold-start figure be skipped; the 22.2s measurement stands as the record.

**Housekeeping confirmed:** the Supabase CLI is linked to dev (`zocfhyysnvptxktqezfk`) — the Task's
premise that it was still on prod was already stale.

## Important Findings

**1. Push revocation was broken in production (fixed).** `DELETE /push/subscribe/{endpoint:path}`
encoded a URL into the request path. Azure Container Apps fronts the backend with Envoy, which
normalizes percent-encoded and duplicate slashes before routing, so the value arrived mangled and
matched no stored row. Locally the request reaches uvicorn directly with no normalization, so the
entire test suite passed against a defect that made **consent non-revocable in production** — a
compliance failure, not a cosmetic one. Now a query parameter. **The general lesson is reusable: any
route carrying a URL, path, or other slash-bearing value in a path segment is untrustworthy behind this
ingress.**

**2. Model-generated URLs are rendered clickable (documented, not fixed — User's explicit decision).**
`Markdown.tsx` runs `marked` with `gfm: true`, which autolinks bare domains, and `'a'`/`href` are
allowlisted in DOMPurify. Every URL in model prose becomes clickable regardless of provenance. Confirmed
live: an uncurated answer about Duolingo rendered `duolingo.com` as a link. This violates "never render
a model-generated URL as a clickable link". The curated Netflix case looks correct only by coincidence —
the renderer never sees provenance, and there is **no typed component for curated links**, so curated
URLs also reach the user only through model prose. Two candidate fixes were scoped: (a) disable GFM
autolinking and drop `'a'` from the allowlist so all chat URLs are plain text — ~10 lines, loses the
curated link's clickability; (b) strip `href` in the DOMPurify hook unless the origin is
project-controlled — preserves curated links, needs an allowlist kept in sync with the seed. The proper
fix is a typed guide-card payload, which is a feature-sized piece of work.

**3. Supabase's built-in email sender will block the beta.** A friend hit
`over_email_send_rate_limit`. Supabase's shared SMTP is throttled to a handful of messages per hour and
is documented as not for production. Every signup sends a confirmation email, so a small group signing
up together locks out everyone after the first few. Custom SMTP must be configured before the app is
shared.

**4. The rate-limit error copy is misleading.** `auth-errors.ts` maps three distinct conditions —
HTTP 429, `over_request_rate_limit`, and `over_email_send_rate_limit` — onto one string that says "Wait
a minute and try again." That is right for the per-minute limit and wrong for the hourly email limit; a
user retries in a minute, fails again, and concludes the app is broken.

**5. Greek translation quality.** The User reports friends finding several Greek strings off. 355 keys
exist with full parity between `en` and `el` (11 identical, brand names). Not yet reviewed for quality —
the User wants a careful pass with findings brought back to them rather than changed unilaterally, and
raised using a Greek-stronger model to check.

**6. The subscription has no spending limit.** `quotaId: PayAsYouGo_2014-09-01`,
`spendingLimit: Off` — despite still being named "Azure for Students". Converting away from the student
quota (needed for Static Web App region compatibility) removed the hard stop, so once credit is
exhausted charges reach a payment method with nothing to halt them. Azure Budgets alert but cannot stop
spend. This materially changes the `--min-replicas 1` decision: estimated ~€8-10/month, but taken
against real money rather than credit.
