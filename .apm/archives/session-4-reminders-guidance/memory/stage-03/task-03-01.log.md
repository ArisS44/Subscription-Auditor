## Important Findings

**1. The web app manifest was served with the wrong MIME type in production.** Azure Static Web Apps
has no built-in mapping for `.webmanifest` and served it as `application/octet-stream`. Because the
site also sends `X-Content-Type-Options: nosniff`, the browser does not fall back to guessing — it
rejects the file as a manifest outright. The request returned a healthy 200, nothing failed in CI, and
the entire PWA identity (installability, name, icons, standalone display) silently did not apply.
**Only a live HTTPS request could reveal this** — exactly the failure class the project's standards
predict. Fixed and redeployed.

**2. Compliance gaps that should shape what comes next.** There is no Privacy Policy page in
`frontend/src`, and no data-export or account-deletion endpoints in the backend routers. Both are
explicit project non-negotiables. The User intends to share the app with a small group of beta testers,
which was advised as acceptable at that scale with honest framing; a wider release should not happen
until these ship.

**3. Turnstile is not verified server-side.** It appears only in
`frontend/src/features/auth/Turnstile.tsx`; nothing in `backend/app` validates the token. A widget the
server does not check is decoration — anyone calling the API directly bypasses it. Relevant before any
open signup link.

**4. The test suite has no timeout configured.** `pyproject.toml` sets only `asyncio_mode = "auto"`.
A test blocking on a database connection or network call does not fail — it sits until GitHub's
six-hour job ceiling. This made a slow suite indistinguishable from a hung one twice during this Task.
Adding `pytest-timeout` would convert a silent hang into a fast, readable failure.

**5. The production CSP still allows dev origins.** `connect-src` includes `http://localhost:8000` and
the dev Supabase project `zocfhyysnvptxktqezfk` alongside the prod origins. Not exploitable, but dev
config riding into production; worth tightening.

**6. Capacity, discussed with the User.** Infrastructure is not the binding constraint — the LLM budget
is. Roughly 20-40 concurrent chat turns (asyncpg pool of 10 per replica, max 2 replicas), and while
`CHAT_GLOBAL_DAILY_CAP` of 2000/day implies ~200 daily users, a fully-used day would exhaust the €10
Gemini prepaid credit in about three days. Separately, `--min-replicas 0` means the first visitor
after idle waits through a cold start — the highest-impact change before showing the app to anyone.

**7. The Supabase CLI is still linked to production.** It must be relinked to dev before further
development work, or a future `db push` will target the wrong project.
