# Task 2.14 - Language & Copy Review

## Summary
Reviewed all user-facing copy — both locale files and the backend's bilingual notification copy — against
the final post-2.15 surface. Removed 17 orphaned strings, corrected copy that had gone stale as features
shipped, and applied four User-selected improvements covering the language switcher, product naming and
Greek naturalness. Parity held throughout at 354 keys.

## Details

**Inventory.** Extracted every key from `en.json`/`el.json` (371 at the start) and cross-referenced them
against every `t()` call in `src/`, accounting for dynamically-composed keys (`chat.tool.${name}`,
`subscriptions.status.${status}`, i18next plural suffixes). Each of the 26 candidates was then verified by
hand before deletion — `chat.tool.*` and `subscriptions.count_other` looked unused but are reached
dynamically and were kept.

**Applied directly (factual corrections, not matters of taste):**
- `overview.roadmap.teaser` still promised renewal reminders as "on the way" although they shipped earlier
  in this Stage — a live page telling users a working feature did not exist. Reworded to invoice import and
  the extension only.
- **17 orphaned keys removed** from both files, notably `dashboard.comingSoon.chat` ("The bilingual AI
  assistant will live here in a future update") now that chat ships. Also `dashboard.title`, four
  `*.placeholder` scaffolding strings, `hello.greeting`/`hello.error`, the whole `nav.*` block,
  `settings.notifications.renewalReminders(+Hint)`, `subscriptions.detail.billingCycle`/`status`, and
  `overview.chartType.label`/`currency.label`.
- English dialogs switched from `"{{name}}"` to `“{{name}}”` (5 strings), matching the curly quotes already
  used elsewhere in English and the consistent «…» in Greek.

**Verified as correctly still reading "unavailable"** — the criterion cuts both ways, and these are all
genuinely unbuilt: the Reports placeholder, the onboarding extension step, `subscriptions.detail.usage.*`,
and the monthly-insights / weekly-summary controls, which remain disabled under the "More reminders"
heading with the Coming soon badge.

**Presented to the User and applied on their selection** (all four accepted):
- **Language switcher labels** → `EN` / `ΕΛ` in both languages. Previously English showed `EN`/`GR` — `GR`
  is the ISO country code for Greece, not the language code (`EL`) — and Greek showed `ΑΓ`/`ΕΛ`. Translating
  a switcher's own labels defeats its purpose, since its reader by definition may not read the active
  language.
- **Product naming** → "Subscription Auditor" everywhere; it had alternated with "Auditor" between the
  landing page, the sidebar and the onboarding welcome. Apollon stays reserved for the assistant. The
  sidebar brand gained `leading-tight`, as the full name wraps to two lines at that width.
- **Greek naturalness** → «Σύνδεση ως» replacing the masculine «Συνδεδεμένος ως»; «Χειροκίνητη προσθήκη»
  replacing the literal «Προσθήκη με το χέρι».
- **Backend reminder copy** → leads with «Η συνδρομή {name}» instead of «Το {name}», since Greek articles
  carry gender and a subscription name may be any gender; and Greek amounts now use a comma as the decimal
  separator.

**`Intl` audit.** `lib/format.ts` uses `Intl.NumberFormat`/`DateTimeFormat` throughout, keyed to the active
language, with the `maximumFractionDigits` correction (the €7.99 → "8" defect) in place — spot-checked
rather than assumed, as instructed. The one place numbers were **not** locale-formatted was the backend
copy module, which composed amounts with a plain `f"{price:.2f}"`; that is the fix above.

## Issues
- The full backend suite was **not** run three times as the Rules require for live-DB regression judgement.
  The change is confined to a pure string-composition module with no database interaction, and the affected
  file passed in full; a full triple run seemed disproportionate. Flagging the deviation rather than
  quietly skipping it — worth a full run before the branch merges.
- Copy changes were not re-verified in a running browser. They are static strings covered by tests and a
  clean build, but the rendered result of the longer product name in the sidebar is a visual change the
  User has not yet seen.

## Compatibility Concerns
- **17 locale keys deleted from both files.** Any in-flight branch that references them will render raw key
  strings. The full list is in the Details section; the ones most likely to be referenced elsewhere are
  `dashboard.title`, `nav.home`, `nav.dashboard` and `hello.greeting`.
- **`_format_price` in `notifications_copy.py` changed signature** — it now takes the resolved language as a
  second argument. It is module-private with a single call site, but any other Worker's branch calling it
  will break.
- **Greek reminder body text changed shape**, so any test asserting on the old «Το {name} ανανεώνεται»
  wording will fail.

## Important Findings
- **Copy goes stale silently as features ship.** Two strings still described shipped features as future
  work, and neither was caught by any test — text-presence tests prove wording exists, never that it is
  *true*. Worth a habit at the end of each Stage: re-read the placeholder copy against what actually
  shipped. This Task found them only because it was scheduled after the features landed.
- **The backend was the one place bypassing `Intl`-equivalent formatting.** The frontend rule ("numbers,
  dates and currencies formatted per the active language") had no backend counterpart, so server-composed
  copy drifted into English number formatting for Greek users. Now fixed for the renewal reminder, but the
  same trap awaits any future server-composed message (the monthly review job especially) — the standard
  should arguably say so explicitly.
- **The `hello.*` namespace is scaffolding left from Session 1** and now holds two generic strings
  (`loading`, `logout`) used across unrelated features. Renaming it to something like `common.*` would be
  tidier but touches several component files; not done, since this Task's remit is copy rather than code
  structure.
- **The client-side password policy from Task 2.15 remains unenforced server-side** until the User updates
  the Supabase dashboard for both dev and prod. Repeated here because it is the one open security item
  spanning this batch.
