# Task 2.6 - Scheduled Cron Workflow

## Summary
Added `.github/workflows/reminders.yml`, a GitHub Actions workflow that triggers the backend's
`POST /api/v1/jobs/run-due` reminder endpoint on a daily cron plus manual dispatch, authenticating with
`PROD_JOB_TOKEN`. All locally-validatable criteria pass; the live end-to-end check is deferred to Stage 3
because the endpoint is not deployed until Task 3.1.

## Details

**Dependency integration (Task 2.2).** Read the actual endpoint at `backend/app/routers/jobs.py`: it is
`POST /jobs/run-due` under the `/api/v1` prefix (`main.py:51`), header `X-Job-Token` compared in constant
time, failing closed with an identical 401 for missing/malformed/wrong/unset-token, returning a
counts-only `JobRunResult` (`due`/`sent`/`skipped_already_sent`/`pruned`/`failed`). Path, header, method,
and response shape all match the Task Prompt exactly — no discrepancy.

**Prod URL confirmed against reality**, not the prompt string. Queried the live Container App ingress
FQDN via `az containerapp show`; it returned
`ca-subscription-auditor-backend.nicebush-826aba8d.germanywestcentral.azurecontainerapps.io`, identical to
the prompt. Full URL used: `https://<fqdn>/api/v1/jobs/run-due`.

**Workflow design.**
- **Triggers:** exactly `schedule` + `workflow_dispatch`. No `push`/`pull_request` — a reminder firing on
  every code change would send real notifications. This inverts the existing workflows' `on:` block, so it
  was written fresh rather than copied.
- **Cron `0 6 * * *` (06:00 UTC).** Target ~08:00 Athens. Athens is UTC+2 (EET, winter) / UTC+3 (EEST,
  summer), so the fixed UTC hour lands 08:00 local in winter and 09:00 in summer. The one-hour DST drift
  and GitHub's under-load scheduling imprecision are documented in a comment next to the cron and in the
  README, so neither is later mistaken for a bug.
- **Token safety:** referenced only as `${{ secrets.PROD_JOB_TOKEN }}`, bound to a step env var and never
  inlined into the command. No `curl -v`, no `set -x` — either would print the `X-Job-Token` header. Not
  relying on GitHub's secret masking alone.
- **Cold start:** the Container App is `minReplicas: 0`, so the first request wakes it. Used
  `--max-time 180 --retry 3 --retry-delay 15 --retry-all-errors` to ride out wake-up latency and transient
  5xx rather than an aggressive timeout.
- **Loud failure:** `set -euo pipefail`, explicit HTTP-status capture via `--write-out '%{http_code}'`,
  and `exit 1` with a `::error::` annotation on any non-2xx or unreachable endpoint. The counts-only body
  (never user content) is surfaced for debugging.
- **`permissions: {}`** — least privilege; the workflow touches no repo scope.

**Documentation** added as `infra/azure/README.md` §8: triggers and what is deliberately absent, the
schedule/timezone rationale, step-by-step manual-dispatch instructions, secret handling, and an explicit
note that live verification is a Stage 3 step.
