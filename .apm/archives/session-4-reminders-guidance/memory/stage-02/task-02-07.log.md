# Task 2.7 - Current-Date Injection in the Chat Prompt

## Summary

`build_system_prompt` now appends the real current date (ISO, computed per request) alongside the language
directive, so the chat model resolves relative dates against today instead of its training-cutoff date. Fixes
the defect found in Task 2.3 where "started today" stored 2025-05-18. Verified live in EN and EL; 193 tests
passing.

## Details

Surgical, as scoped — a per-request prompt addition plus tests, no redesign.

- Added `from datetime import date` and, in `build_system_prompt`, a date directive built from
  `date.today().isoformat()` at call time. Deliberately not a module-level constant: `_APOLLON_IDENTITY` and
  the two prompt constants are evaluated once at import, so a date baked there would freeze at process start
  and drift wrong across midnight in a long-running server.
- The directive states today's date and instructs the model to resolve relative expressions ("today",
  "yesterday", "last month") against it, with explicit wording that this does NOT license defaulting a date
  the user never gave — an add with no start date must still ask. This keeps the anti-fabrication rule from
  Task 2.3 intact; the two ideas are kept distinct in the text.
- Placed as its own "Current date:" block before the existing "Language:" block; the language directive is
  unchanged.

No subagents, no correction loop.

## Output

- `backend/app/services/prompts.py` — `build_system_prompt` injects the per-request date.
- `backend/tests/test_prompts.py` — three new tests: date present in ISO form, wording preserves the
  no-defaulting rule, and the date is computed per call (patched `date.today()` → new value appears, proving
  it is not frozen at import).
- Commit `74f4afb` on `fix/chat-current-date`. Not pushed.

## Validation

- **Per-request, not frozen:** `test_current_date_is_computed_per_call_not_frozen_at_import` patches
  `prompts.date` to a fixed 2099-01-02 and asserts it appears — proving no import-time capture.
- **Present + formatted:** the assembled prompt contains today's ISO date in every variant.
- **Anti-fabrication preserved:** a test locks in the "does not permit ... still ask for it" wording; the 2.3
  classification-vs-fabrication tests still pass.
- **Full suite:** 193 passed, 0 failed on the first run; ruff/black clean.

**Live verification (EN + EL), real today = 2026-07-25 — all three behaviours pass:**
- relative: "Add Netflix ... started today" stored `start_date = 2026-07-25` with `next_renewal_date =
  2026-08-25` (was 2025-05-18 before this fix), in both languages;
- absent: "Add a Hulu subscription" (no date) → the model asked for price/cycle/start date rather than
  defaulting to today, in both languages;
- absolute: "Add Spotify ... started on 3 March 2026" stored `start_date = 2026-03-03` with a correct
  `next_renewal_date = 2026-08-03`, in both languages.
DB rows confirmed the stored dates directly, not just the model's prose.
