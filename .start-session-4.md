# Start Session 4 — Guidance, Insights & Reports

Quick reference for kicking off the next APM session. Run the terminal commands
in order, then start the Planner in a NEW chat.

## 1. Terminal commands (run in the repo root)

```bash
# Scaffold a fresh, blank .apm/ workspace for Session 4.
# (Session 1 is archived at .apm/archives/session-1-foundation/
#  Session 2 is archived at .apm/archives/session-2-subscription-crud-dashboard/
#  Session 3 is archived at .apm/archives/session-3-ai-chatbot-onboarding/)
apm init
```

## 2. Start the Planner (in a NEW chat / new Claude Code terminal)

```
/apm-1-initiate-planner
```

## 3. First message to the Planner — paste this:

```
We're starting Session 4 of the SaaS Subscription Auditor project.

Full project context:
- Project spec: @docs/APP_DESCRIPTION.md
- Session plan: @docs/APM_SESSIONS.md
- Engineering standards: @docs/ENGINEERING_STANDARDS.md
- Cross-session decisions: @docs/DECISIONS.md

This session scope: **Session 4 — Guidance, Insights & Reports**
(see the Session 4 section in @docs/APM_SESSIONS.md).

Sessions 1 (Foundation & Deployment Pipeline), 2 (Subscription CRUD & Dashboard
Core), and 3 (AI Chatbot & Onboarding) are complete and archived at
.apm/archives/session-1-foundation/, .apm/archives/session-2-subscription-crud-dashboard/,
and .apm/archives/session-3-ai-chatbot-onboarding/ — read their session-summary.md
files (if present) or Memory/index.md for what already exists: auth, RLS data
layer, deployed prod pipeline (S1); the full subscriptions CRUD + analytics API
and dashboard UI (S2); Apollon — the bilingual, tool-calling chatbot (Gemini-
backed, Groq as fallback), inline chart/table visuals, resumable onboarding,
currency conversion, and Turnstile CAPTCHA, all live in production (S3).
Produce a Session-4-scoped Spec/Plan/Rules only, not the whole project.
```

## 4. After the Planner finishes

Start a Manager in this same chat (or a fresh one):

```
/apm-2-initiate-manager
```

Then follow the Manager's dispatch instructions.

## Reminders carried over from Sessions 1-3

- `main` is deployable; **pushing to `main` triggers the production deploy workflows.**
- Dev and prod are independent Supabase projects — new tables (Session 4 needs at
  least `service_guides`, and likely a `reports` table) need migrations applied to
  BOTH; prod auth settings are configured separately.
- **The Supabase CLI is currently linked to PROD** (`ylwjevannrlsauegwbas`), left
  that way at the end of Session 3's prod migration. Run
  `supabase link --project-ref zocfhyysnvptxktqezfk` before any dev migration work.
- `supabase db push` needs `supabase login` (an access token) in addition to the
  relink — the relink alone does not authenticate the Management API push. This
  has bitten every session's first migration Task so far.
- Prod URLs: frontend https://red-tree-0557d7c03.7.azurestaticapps.net ;
  backend Container App `ca-subscription-auditor-backend` (scale-to-zero).
- Backend pytest's full suite intermittently fails 1-3 live-DB tests (a different
  one each run) due to Supabase free-tier Auth Admin API rate limiting /
  connection-pooler drops under back-to-back test-user creation — known
  flakiness across all three sessions so far, not a regression, if the same test
  doesn't fail on an isolated rerun.
- **LLM provider is Gemini Flash-Lite** (`gemini-flash-lite-latest`), migrated
  from Groq in Session 3 after Groq's free-tier rate limit proved impractical for
  real multi-user use (`docs/DECISIONS.md` 2026-07-13). Groq remains a selectable
  fallback adapter behind `llm.py`. Running on paid Google Cloud Prepay (~€10,
  auto-reload off, a genuine hard cap) — `CHAT_GLOBAL_DAILY_CAP=2000` is the
  app-level tripwire. `gemini-flash-lite-latest` is a moving alias, not a pinned
  version — worth pinning to a dated model if reproducibility becomes a concern.
  Any new tool argument model or provider adapter should re-check schema
  tolerance (Groq rejects Pydantic `pattern`/`format`; Gemini needs `anyOf`/`$ref`
  flattened) — see the Session 3 archive's Memory notes for the full list of
  provider-specific gotchas (including a `thoughtSignature` replay requirement
  and a history-window-must-start-at-a-user-turn constraint for Gemini).
- Two items deliberately deferred out of Session 3, not yet scheduled:
  - **Chat multi-currency chart quality.** For multi-currency portfolios, the
    chat agent flattens mismatched-scale currencies into one meaningless chart,
    and can't convert currencies in-chat (no FX-convert tool registered, despite
    the app having a full FX layer). Left as-is for Session 3
    (`docs/DECISIONS.md` 2026-07-16). The small fix (one chart per currency, or
    ask which currency) vs. the bigger fix (a real FX-convert tool / base-currency
    `get_analytics` mode) are both still open — worth deciding if Session 4 touches
    analytics tools at all.
  - **Extension time-tracking scope broadened.** The User wants the future browser
    extension's usage/time tracking to cover as many subscriptions as technically
    feasible, not just AI-tools-only as `docs/APP_DESCRIPTION.md` currently frames
    it (caveat: a browser extension can only ever measure browser-based/web-app
    usage). Not Session 4's concern directly (extension is Session 6), but worth
    reconciling in the spec before that session's Planner starts.
- `backend/scripts/chat_repl.py` is a throwaway live-testing REPL harness from
  Session 3 — untracked, never committed, safe to ignore or delete.
